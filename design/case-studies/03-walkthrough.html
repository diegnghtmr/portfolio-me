System walkthrough

  1. Planning without official records

    Brújula was scoped to one institution while the boundaries between curriculum, progress and simulation were still being defined. Students declare their own academic data; these declarations are not official records.

  2. Two repositories, two responsibilities

    The Spring Boot backend houses the modules, API contract and local infrastructure configuration. The browser app handles catalog, curriculum, progress, import and simulation.

  3. How the contract crosses the boundary

    The backend owns the OpenAPI contract. The frontend tracks a copy of that contract and calls the API through a generated Axios client.

  4. One process instead of microservices

    Spring Modulith keeps the modules in one Spring Boot process. That avoids the overhead of a distributed system, but all modules share one JVM and deployment lifecycle.

    ADR-001: Modular monolith ↗

  5. Contract-first over validation alone

    The ADR weighs a hand-written contract, validation only, and server and client generation. It makes the backend contract authoritative. Generation reduces drift, but contract changes require syncing the copy and regenerating the client.

    ADR-006: OpenAPI contract-first ↗

  6. Staff see aggregates, not individual grades

    The MVP gives staff aggregates only. Helping an individual student would require a delegated access feature later.

    ADR-012: Staff access ↗

  7. What the CI workflow defines

    The CI workflow defines formatting, test and coverage gates. It runs locally or by hand; no remote runner is configured.
