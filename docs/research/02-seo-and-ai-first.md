# Research brief: search- and agent-readable developer portfolio

**Bottom line:** Build an excellent, crawlable portfolio first; add agent-specific interfaces only where they serve a real client. Google says AI Overviews and AI Mode have **no special optimization requirements**: supporting pages must be indexed and eligible for a search snippet. [Google](https://developers.google.com/search/docs/appearance/ai-features)

## 1. Technical SEO checklist

- **Rendering and content.** Prefer SSG for mostly static profile and project pages; use SSR when content genuinely needs it. Ensure meaningful text and links appear in rendered HTML, not solely behind client-side interaction. Publish specific project descriptions, outcomes, technologies, and links to evidence. [Google Search Essentials](https://developers.google.com/search/docs/essentials); [Google AI guidance](https://developers.google.com/search/docs/appearance/ai-features)
- **Metadata and languages.** Give each page a distinctive title and description. Use stable `/en/` and `/es/` URLs, each with its own absolute canonical; connect equivalent pages with reciprocal `hreflang="en"` and `hreflang="es"` links, including self-references. Use `x-default` only where a suitable fallback exists. [Canonical](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls); [localized pages](https://developers.google.com/search/docs/specialty/international/localized-versions)
- **Discovery.** Publish `sitemap.xml` with canonical, indexable URLs and reference it in `robots.txt`; permit relevant search crawlers. Submit and monitor the site in [Google Search Console](https://search.google.com/search-console/about) and [Bing Webmaster Tools](https://www.bing.com/webmasters/about). Use [IndexNow](https://www.indexnow.org/) to notify participating engines of changes; notification is **not** an indexing guarantee. [Google sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)
- **Social sharing.** Set per-page Open Graph title, description, canonical URL and image. Dynamic OG image generation is useful for projects or articles, but cache images and verify that social crawlers can fetch them; it is a sharing enhancement, not an established ranking lever. [Open Graph protocol](https://ogp.me/)
- **Core Web Vitals.** At the **75th percentile** of real visits, target LCP **≤2.5 s**, INP **≤200 ms**, and CLS **≤0.1**, separately for mobile and desktop. Optimize image delivery, font/layout stability and JavaScript interaction cost. [web.dev](https://web.dev/articles/vitals)
- **JSON-LD.** Model what is visibly present: `ProfilePage` with `mainEntity: Person`, linking `sameAs` to genuine GitHub and LinkedIn profiles; `WebSite` for the site; `SoftwareSourceCode` for actual repositories/code; `CreativeWork` for projects or articles; `ItemList` for a project listing; and `BreadcrumbList` for real navigation. Use stable IDs to connect entities. Validate with [Rich Results Test](https://search.google.com/test/rich-results) and [Schema Markup Validator](https://validator.schema.org/). Schema.org validity does **not** imply a Google rich result; Google documents specific eligibility rules for [ProfilePage](https://developers.google.com/search/docs/appearance/structured-data/profile-page) and [breadcrumbs](https://developers.google.com/search/docs/appearance/structured-data/breadcrumb). [Schema.org](https://schema.org/)

## 2. AI-first / agent-readable

- **Readable pages first.** Use semantic headings, navigation, descriptive links, clear authorship and factual text; make project facts available without requiring an agent to operate a UI. Keep structured data consistent with visible content. [Google](https://developers.google.com/search/docs/appearance/ai-features)
- **`llms.txt`: optional experiment.** The [llmstxt.org proposal](https://llmstxt.org/) specifies a Markdown guide with an H1 and optional summary and categorized links. It also proposes discoverable `.md` alternatives via `rel="alternate"`. A full-site `/llms-full.txt` is a separate convention, **not a requirement in that proposal**. Adoption remains limited: HTTP Archive observed valid files on about **2.1%** of desktop/mobile sites in its July 2025 crawl. [Web Almanac](https://almanac.httparchive.org/en/2025/generative-ai#llmstxt)
- **Markdown representations.** Optional `.md` routes can provide clean versions of individual pages. Alternatively, honor `Accept: text/markdown` on the HTML URL and return `Content-Type: text/markdown` plus `Vary: Accept` so caches separate variants. Test for lost links or content. [Proposal](https://llmstxt.org/); [Cloudflare implementation](https://developers.cloudflare.com/fundamentals/reference/markdown-for-agents/)
- **Choose crawler policy deliberately.** Allow `OAI-SearchBot` and `PerplexityBot` if ChatGPT and Perplexity search visibility is desired; `GPTBot` and `ClaudeBot` are separately relevant to training. `Google-Extended` controls specified Gemini/Vertex AI uses, **not Google Search indexing**. Blocking a search bot can reduce discovery; allowing one guarantees no citations. Robots directives are not access control. [OpenAI](https://developers.openai.com/api/docs/bots); [Perplexity](https://docs.perplexity.ai/guides/bots); [Anthropic](https://support.anthropic.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler); [Google](https://developers.google.com/crawling/docs/crawlers-fetchers/google-common-crawlers)
- **NLWeb and MCP:** [NLWeb](https://github.com/microsoft/NLWeb) is an experimental natural-language interface whose endpoints can serve MCP clients. A small read-only MCP server exposing profile, projects and skills could be useful for **known, configured agents**, but adds hosting and maintenance; it is not a search-indexing shortcut. Document the endpoint explicitly. Do not assume a universal `/.well-known/mcp` discovery convention: MCP’s standardized well-known mechanisms concern, among other things, [authorization metadata](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization).

## 3. Evidence versus hype

- **Evidence:** Google explicitly says no special AI files or schema are needed for its AI features. In Ahrefs’ 2025 sample, **86% of AI Overview-cited pages ranked somewhere in Google’s top 100**; this is correlation, not proof that rank causes citation. [Google](https://developers.google.com/search/docs/appearance/ai-features); [Ahrefs](https://ahrefs.com/blog/search-rankings-ai-citations/)
- **Platform differences matter:** In a separate Ahrefs analysis, only **12% of AI-cited URLs** overlapped Google’s top 10 for the original prompt, on average. Do not extrapolate Google AI Overview results to ChatGPT or Perplexity, or assume one study predicts a personal portfolio’s visibility. [Ahrefs](https://ahrefs.com/blog/ai-search-overlap/)
- **Hype:** Claims that `llms.txt`, Markdown, MCP, or a particular schema type *guarantee* AI citations are unsupported by the evidence above. Measure referral traffic, crawl access and representative platform citations separately; prioritize accurate, distinctive, independently verifiable work over speculative GEO tricks. [Google](https://developers.google.com/search/docs/appearance/ai-features); [Web Almanac](https://almanac.httparchive.org/en/2025/generative-ai#llmstxt)
